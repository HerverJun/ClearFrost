# 清霜V3 低配工控机性能深度评审报告

- 评审日期: 2026-03-02
- 代码基线: `473bdb0`
- 评审范围: `ClearFrost`（YOLO链路、PLC链路、WebView2链路、存储/数据库链路）
- 评审方式: 静态代码审计 + 关键路径开销建模（未在目标工控机实机压测）

---

## 1. 执行结论（TL;DR）

当前版本已经做了不少性能优化（异步图像保存、工业渲染模式、WebView2 图像降采样、统计批量落盘等），**在低配工控机上可运行**，但要稳定跑长时间和高节拍，仍有几个关键瓶颈：

1. `PLC` 检测临界区过长，包含了多次 `await` 的前端通信，导致触发拥塞风险。
2. `重拍 + 多模型回退` 在极端场景会放大推理次数，低配 CPU/GPU 下延迟抖动明显。
3. 图像保存链路存在多次 `Mat.Clone()`，内存带宽和 GC/非托管内存压力偏高。
4. 数据库每次写入都新建连接，eMMC/SATA 低速盘下会放大抖动。
5. `YoloResult.BasicData` 每次读取分配新数组，在渲染热路径产生不必要分配。

整体建议：先做 3~5 个“低风险高收益”改造，再上目标工控机做 50~200 轮压测定标。

## 3. 关键链路开销模型

### 3.1 PLC 自动检测主链路（当前实现）

1. PLC 触发入队。
2. `HandlePlcTriggerAsync` 获取 `_detectionSemaphore`。
3. 触发拍照 / 回退缓存帧。
4. YOLO 推理（可能主模型 + 辅助1 + 辅助2）。
5. ROI 过滤。
6. 渲染并推送 WebView2 图像。
7. 写 PLC 结果。
8. 更新统计、前端日志、结果状态。
9. 异步入队图像保存 + 异步数据库写入。
10. 释放 `_detectionSemaphore`。

核心证据: `ClearFrost/Views/主窗口.PLC.cs:86-390`

### 3.2 最坏推理放大系数（按代码逻辑）

- 重拍循环: `for (attempt = 0; attempt <= maxRetries; attempt++)`  
  证据: `ClearFrost/Views/主窗口.PLC.cs:118`
- 多模型回退: 主模型 -> 辅助1 -> 辅助2（串行）  
  证据: `ClearFrost/Core/MultiModelManager.cs:342-452`

最坏推理次数公式:

`(MaxRetryCount + 1) * (1 + 已启用辅助模型数)`

默认配置（`MaxRetryCount = 1`, `EnableMultiModelFallback = false`）: 最坏 2 次推理。  
开启双辅助回退后: 最坏 6 次推理。  
证据: `ClearFrost/Config/AppConfig.cs:78`, `ClearFrost/Config/AppConfig.cs:83`

## 5. 重点问题清单（按优先级）

## P1-1 检测临界区过长，吞吐上限受 UI/日志影响

- 现象:
  - `_detectionSemaphore` 从入口到收尾全程持有。
  - 临界区内包含多次 `await` 到 WebView2（图像、日志、状态更新）。
- 证据:
  - 获取/释放信号量: `ClearFrost/Views/主窗口.PLC.cs:92`, `ClearFrost/Views/主窗口.PLC.cs:389`
  - 图像推送: `ClearFrost/Views/主窗口.PLC.cs:237`, `ClearFrost/Views/主窗口.PLC.cs:241`
  - 检测日志/结果更新: `ClearFrost/Views/主窗口.PLC.cs:313`, `ClearFrost/Views/主窗口.PLC.cs:316`
  - `WriteDetectionResult` 内还会写前端日志: `ClearFrost/Views/主窗口.PLC.cs:431-437`
- 风险:
  - WebView2 忙或 JS 执行慢时，PLC 触发处理变慢，触发队列积压甚至丢弃。
- 建议:
  - 将“写 PLC 结果”保留在临界区，`UpdateImage/LogDetection/UpdateResult` 改为临界区外异步派发。
  - `WriteDetectionResult` 拆分为“纯PLC写入函数”和“前端日志函数”。

## P1-2 重拍与多模型回退叠加，低配机延迟抖动大

- 现象:
  - 失败后重拍，且每次推理可串行切换到多辅助模型。
- 证据:
  - 重拍循环: `ClearFrost/Views/主窗口.PLC.cs:118-127`
  - 多模型串行回退: `ClearFrost/Core/MultiModelManager.cs:342-452`
- 风险:
  - 当目标难检出时，单次触发时延被乘法放大，吞吐下降明显。
- 建议:
  - 低配工控机默认关闭回退或只启用 1 个辅助模型。
  - 对回退设置“总耗时上限”（例如超时即直接 NG 回写）。

## P1-3 图像保存路径有多次 clone，内存/带宽压力偏高

- 现象:
  - PLC路径多处克隆，入队时又克隆一次。
- 证据:
  - `lastFrameForSave = frameToProcess.Clone()`: `ClearFrost/Views/主窗口.PLC.cs:205`
  - 异步保存前再次 `Clone`: `ClearFrost/Views/主窗口.PLC.cs:321-324`
  - 入队再次 `image.Clone()`: `ClearFrost/Services/ImageSaveQueue.cs:51`
- 风险:
  - 高频触发下会造成明显内存带宽浪费，增加非托管内存分配/回收压力。
- 建议:
  - 给 `ImageSaveQueue` 增加“所有权转移入队（不再 clone）”接口。
  - 在调用侧明确谁负责 `Dispose`，减少重复拷贝层数。

## P1-4 SQLite 每条记录新建连接，低速存储设备抖动明显

- 现象:
  - 每次 `SaveDetectionRecordAsync` 都 `new SqliteConnection + OpenAsync`。
- 证据:
  - `ClearFrost/Services/SqliteDatabaseService.cs:79-106`
  - 打开连接: `ClearFrost/Services/SqliteDatabaseService.cs:85-86`
- 风险:
  - eMMC/低端 SATA 上会放大写入延迟波动。
- 建议:
  - 启用 `WAL` 与 `synchronous=NORMAL`。
  - 增加数据库批量写队列（例如 20~100 条批写）。

## P1-5 `YoloResult.BasicData` getter 每次分配新数组（热路径分配）

- 现象:
  - `BasicData` getter 每次返回 `new float[]`。
- 证据:
  - `ClearFrost/Yolo/YoloDataTypes.cs:25-30`
  - 渲染热路径频繁访问: `ClearFrost/Yolo/YoloRenderer.cs:157`, `ClearFrost/Yolo/YoloRenderer.cs:337`, `ClearFrost/Yolo/YoloRenderer.cs:687-691`
- 风险:
  - 检测框数量增加时，产生额外托管分配和 GC 压力。
- 建议:
  - 改为字段直读（`CenterX/CenterY/...`）或缓存结构体，不在 getter 分配数组。

## P2-1 预处理/后处理并行策略可能与 ORT 线程叠加，低核CPU不稳定

- 现象:
  - YOLO前后处理大量 `Parallel.For/ForEach`，ORT 本身也有线程并行。
- 证据:
  - ORT线程配置: `ClearFrost/BW_yolo.cs:388-390`
  - 预处理并行: `ClearFrost/Yolo/YoloPreprocessor.cs:141`, `ClearFrost/Yolo/YoloPreprocessor.cs:220`
  - 后处理并行: `ClearFrost/Yolo/YoloPostprocessor.cs:52`, `ClearFrost/Yolo/YoloPostprocessor.cs:148`, `ClearFrost/Yolo/YoloPostprocessor.cs:652`
  - NMS并行: `ClearFrost/Yolo/YoloNms.cs:50`
- 风险:
  - 2~4 核工控机上出现线程争抢/上下文切换抖动，P95 上升。
- 建议:
  - 增加配置项控制 `MaxDegreeOfParallelism`。
  - 小数据量路径关闭并行，按阈值走串行。

## P2-2 每次检测都写性能日志到文件，I/O 与寿命压力可观

- 现象:
  - `WritePerformanceProfileLog` 在手动/PLC检测后均可能写盘。
- 证据:
  - PLC调用: `ClearFrost/Views/主窗口.PLC.cs:370`
  - 写入实现: `ClearFrost/Views/主窗口.Vision.cs:498-528`
  - 实际文件写: `ClearFrost/Services/StorageService.cs:145-147`
- 风险:
  - 低速盘和长期运行下，写放大明显。
- 建议:
  - 增加“性能日志开关/采样率”（例如每 10 次写一次）。
  - 高负载时只保留聚合指标（P50/P95）。

## P2-3 配置保存调用点较多，存在不必要同步写盘

- 现象:
  - `_appConfig.Save()` 分散在多个 UI 事件处理中。
- 证据:
  - 代表位置: `ClearFrost/Views/主窗口.Init.cs:264`, `ClearFrost/Views/主窗口.Init.cs:734`, `ClearFrost/Views/主窗口.Init.cs:1370`
  - 实际写盘: `ClearFrost/Config/AppConfig.cs:179`
- 风险:
  - 配置频繁改动场景下对 eMMC 不友好。
- 建议:
  - 增加 500ms~2s 去抖保存或“脏标记 + 定时批量保存”。

## P3-1 历史日志读取是“读全文件后再拆分”

- 现象:
  - `SendDetectionLogs` 对每个日志文件 `ReadAllText`，再字符串分割。
- 证据:
  - `ClearFrost/Views/WebUIController.cs:891-895`
- 风险:
  - 历史日志很多时，打开日志页会卡顿。
- 建议:
  - 改为倒序分页读取，限制单次读入字节数。

## P3-2 存在无生产者消费线程（冗余线程管理）

- 现象:
  - `m_frameQueue` 与 `DisplayThread` 仅见消费，未见入队生产代码。
- 证据:
  - 定义: `ClearFrost/Views/主窗口.Fields.cs:104`
  - 消费: `ClearFrost/Views/主窗口.Camera.cs:238-249`
- 风险:
  - 运行开销虽小，但增加代码复杂度和维护成本。
- 建议:
  - 清理死代码或补齐生产逻辑，避免误判系统行为。

## 6. 低配工控机建议配置（先不改代码）

1. 使用 `Release + x64` 发布运行，不要长期用 Debug。
2. 默认保持 `IndustrialRenderMode = true`。  
   证据: `ClearFrost/Config/AppConfig.cs:62`
3. 默认关闭多模型自动切换，或仅启用 1 个辅助模型。  
   证据: `ClearFrost/Config/AppConfig.cs:78`
4. 保守设置 `MaxRetryCount`（建议 0~1）。  
   证据: `ClearFrost/Config/AppConfig.cs:83`
5. 先保守轮询周期（`PlcPollingIntervalMs` 不低于 200~500ms），按现场再调。  
   证据: `ClearFrost/Config/AppConfig.cs:19`

## 7. 建议实施顺序（按收益/风险比）

### 第一批（1~2天，可快速见效）

1. 缩短 `PLC` 检测临界区（UI调用移出信号量范围）。
2. `Sqlite` 开启 `WAL`，并将写入改批量队列。
3. 增加性能日志采样开关，降低每次检测写盘。

### 第二批（2~4天，结构优化）

1. 改造 `YoloResult.BasicData`，去掉热路径分配。
2. 图像保存改“所有权转移入队”，减少 clone 层级。
3. 并行策略阈值化（小任务串行，大任务并行）。

### 第三批（按需）

1. 历史日志分页读取。
2. 清理 `m_frameQueue/DisplayThread` 冗余逻辑。

## 8. 目标机验收方案（必须执行）

建议在目标工控机执行三类测试:

1. 吞吐与延迟:
   - 连续触发 200 次，记录 `P50/P95/P99` 总时延与推理时延。
2. 稳定性:
   - 连续运行 4~8 小时，观察内存曲线与触发丢失率。
3. 存储压力:
   - 打开图像保存 + 数据库写入 + 性能日志，检查磁盘写入峰值与抖动。

建议验收阈值（可按现场再收紧）:

1. `P95` 总耗时 <= 500ms（无重拍）；
2. 触发丢失率 <= 0.1%；
3. 内存无持续上升趋势（30分钟窗口内稳定）。
