# 现场调试与验收指南

本文面向产线调试、设备维护和交付验收。目标是快速判断相机、PLC、模型、存储、数据库和队列是否满足上线条件。

## 打开诊断/调试页面

1. 启动 ClearFrost。
2. 点击顶部工具栏的“诊断/调试”按钮。
3. 点击刷新按钮，确认相机状态、PLC 状态、当前模型、最近 InspectionId、P95/P99、图像队列、记录队列、最近错误、磁盘和内存。

## 检查相机

1. 在主界面启动系统，确认顶部“相机”状态变为已连接。
2. 打开“诊断/调试”，点击“单步取图”。
3. 结果为“单步取图成功”且画面刷新，说明相机、触发取帧和 WebUI 预览链路可用。
4. 若失败，优先检查相机电源、网线/USB、序列号、曝光、触发模式和 SDK DLL。

## 测试 PLC

1. 在设置中确认 PLC IP、端口、协议、驱动和地址配置。
2. 启动系统或手动连接 PLC，确认顶部“PLC”状态为已连接。
3. 在“诊断/调试”点击“PLC 写入测试”。
4. 该操作会向当前结果地址写入测试值，页面会要求二次确认，并写入操作审计。
5. 若失败，检查 PLC 网络、防火墙、地址格式、寄存器权限和当前协议模式。

## 单步推理

1. 确认当前模型已加载。
2. 确认相机已连接并处于采集状态。
3. 在“诊断/调试”点击“单步推理”。
4. 系统会取一帧相机图像并执行一次 YOLO 推理，结果会显示在主画面和调试结果中。
5. 若提示模型未加载，先在模型配置中选择主模型，或检查 ONNX 文件和运行时依赖。

## 条码读取测试

1. 确认 PLC 已连接。
2. 确认条码地址、字长和编码配置正确。
3. 在“诊断/调试”点击“条码读取测试”。
4. 若读取为空，检查扫码枪、PLC 字符串写入方向、字节序、编码和地址偏移。

## 导出诊断包

1. 在“诊断/调试”点击“一键导出诊断包”。
2. 诊断包默认输出到日志目录下的 `Diagnostics` 文件夹。
3. 诊断包包含 health snapshot、startup diagnostics、最近检测阶段耗时、最近错误、模型 probe 摘要、队列状态、脱敏配置、模型注册表摘要和轻量日志。
4. 诊断包不打包 ONNX 模型和大体积图片。

## 运行压测

1 小时压测：

```bash
dotnet run --project tools/ClearFrost.SimStress/ClearFrost.SimStress.csproj -c Debug -- --duration-minutes 60 --parallel 4 --output artifacts/simstress_1h.md
```

8 小时压测：

```bash
dotnet run --project tools/ClearFrost.SimStress/ClearFrost.SimStress.csproj -c Debug -- --duration-minutes 480 --parallel 4 --output artifacts/simstress_8h.md
```

固定循环压测：

```bash
dotnet run --project tools/ClearFrost.SimStress/ClearFrost.SimStress.csproj -c Debug -- --cycles 10000 --parallel 4 --output artifacts/simstress_10000.md
```

报告会生成 Markdown 摘要和同名 JSON，包含平均耗时、P95、P99、失败数、队列 backlog、内存变化和吞吐。

## 上产线判断

建议同时满足以下条件后再进入产线：

- 启动诊断无阻塞项。
- 相机单步取图稳定成功。
- 单步推理能返回预期目标或明确 NG 原因。
- PLC 写入测试和条码读取测试成功。
- 诊断包可导出，且不包含大体积图片或明文敏感路径。
- 1 小时压测失败数为 0，P99 满足节拍要求，队列 backlog 不持续增长。
- 8 小时压测内存变化可接受，磁盘剩余空间充足，图像队列和记录队列不接近容量上限。

若任一项不满足，不建议直接上产线，应先定位硬件、模型、PLC 地址、存储或数据库瓶颈。
